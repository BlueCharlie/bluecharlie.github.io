I designed and developed TConfig, a Windows desktop application supporting multiple weighing instruments, including PR5170. It brings weight monitoring, serial setup, measurement and application settings, device information, and calibration controls into one operator interface. An Electron service connects these workflows to the instrument through RS232/SBI and RS485/Modbus RTU.

My work: Designed the operator workflows, developed the desktop application and serial integration, and verified protocol behavior with instrument manuals, serial traces, and real-device feedback.

The engineering decisions

TCONFIG · V2.0.0

Live weights and parameter replies share a serial connection, and delayed responses can overwrite a user’s edits or be mistaken for new weight data. Calibration-parameter reads also need to retrieve existing values without entering a control mode. The application must keep the operator’s intent, displayed values, and instrument state aligned.

  • Checked command syntax, field lengths, units, and numeric encodings against instrument manuals and observed serial traffic.
  • Enabled routine weight polling on the weighing page and coordinated queued parameter operations with that polling.
  • Added page-specific read and write feedback, input protection, and readback comparisons for advanced measurement and calibration-weight parameters.
  • Packaged the Windows application with its native serial dependencies and added focused regression and resource checks for delivery.
Design details & validation

Route each reply to its request

A tare query can return a frame that resembles a live weight. Pending parameter requests match and consume their replies before ordinary weight events are published. Calibration frames identify the point number before parsing the weight value, keeping C1/C2/C3 labels out of the numeric result.

Keep edits separate from confirmed values

Advanced measurement forms protect fields being edited and retain a separate record of confirmed instrument values. Writes run in sequence, followed by delayed readback and comparison. Field-level feedback reports mismatches or failures, while calibration-weight writes use their own numerical readback checks.

Read calibration weights without entering calibration

Dedicated passive queries replaced an earlier control-mode probing path. The serial service restricts commands during these reads, uses a read-only Modbus fallback when needed, and shares concurrent requests. Missing optional points retain an explicit default marker. Seven simulated-serial regression tests cover these read boundaries.

Package a consistent Windows application

The installer includes the native serial module and a checked font subset. FontTools/WOFF2 subsetting reduced the shipped font from 30.7 MB to approximately 0.21 MB while preserving required characters and variable weights. The application also retains its existing data directory after the TConfig rename, preserving access to local account and registration records.
